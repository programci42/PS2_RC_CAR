1. Proje tek cümlede

PlayStation 2'nin USB portuna takılan Seda Elektronik 8'li HID röle kartını DualShock koluyla süren bir homebrew uygulaması. Kola basılı tutunca röle çeker, bırakınca bırakır.

Araçta dört adet RS-540 motor vardır: iki sol motor paralel bir grup, iki sağ motor paralel bir gruptur. Röle 1-2 sol grubun, röle 3-4 sağ grubun iki motor ucunu sürer.

ÜçgenGeri2 + 418 + 20
YuvarlakSağa tank dönüşü1 + 417 + 20

Kart VID 0x178E / PID 0x07D9 ile tanınır. Bu değerler program içinden (ayarlar ekranından) değiştirilebilir ve hafıza kartına kaydedilir.

2. Dört katman — kim ne yapıyor

PS2'de bir USB cihazı sürmek tek dosyalık bir iş değil, çünkü konsolun içinde iki ayrı işlemci var ve USB donanımı bunlardan sadece birine bağlı. Projenin tuhaf görünen bölünmüşlüğünün tek sebebi bu.

EE — Emotion Engine main.c

Ana işlemci (MIPS R5900, 300 MHz). Senin "uygulaman" burada çalışır: ekrana yazı basma, kolu okuma, menüler, hafıza kartı, şifre ekranı. USB donanımına doğrudan erişemez.

IOP — I/O Processor iop/seda_relay_irx.c

Yardımcı işlemci (MIPS R3000, 36 MHz — aslında PS1'in CPU'su). USB, hafıza kartı, CD sürücü, ses gibi tüm çevre birimleri buna bağlı. USB paketini fiilen gönderen taraf burasıdır. IOP'ta çalışan modüllerin uzantısı .irx'tir.

usbd.irx Sony'nin hazır modülü

Sony'nin yazdığı USB host yığını. Cihaz takıldığında enumerate eder, descriptor'ları okur, ve sceUsbd* fonksiyonlarını sunar. Sen bunu yazmıyorsun, PS2SDK'dan alıp ELF'in içine gömüyorsun.

Röle kartı donanım

USB HID cihaz olarak görünür. İçindeki mikrodenetleyici, gelen 1 baytlık komuta bakıp ilgili röleyi çeker veya bırakır. Röleler kendi durumlarını kartın içinde tutar (latch).

Neden IRX'ler ELF'in içine gömülü? Program CD'den veya USB'den çalışabilsin diye. Eğer .irx dosyalarını ayrı tutsaydın, program "bunları diskte nerede bulacağım?" problemine düşerdi. bin2c aracı IRX dosyasını bir C dizisine (unsigned char usbd_irx[] = {...}) çevirir, program da onu bellekten yükler. Tek dosya, sıfır bağımlılık.

3. Bir tuşa basınca ne oluyor

X tuşuna bastığın andan rölenin "tık" demesine kadar geçen yol:

[1] padRead() EE kol durumu okunur | [2] pressed_buttons & PAD_CROSS EE "yeni basıldı" tespiti | [3] relay_set(0, 1) EE röle 0, durum ON | komut = 1 seçilir [4] SifCallRpc(...) EE ---> IOP'a çağrı gönder | (SIF donanım köprüsü) [5] rpc_handler() IOP çağrı karşılanır | [6] seda_send_command(1, mod) IOP 8 baytlık rapor hazırlanır | byte[0]=0x01, byte[3]=0x01 [7] sceUsbdInterruptTransfer() IOP ---> usbd.irx | [8] USB interrupt OUT paketi USB ---> kablodan kartın | interrupt endpoint'ine [9] kart komutu çözer HW röle 1 çeker | [10] transfer_done() callback IOP sonuç geri döner | [11] SifCallRpc geri döner EE ekrana result/status yazılır

Tuş bırakıldığında aynı yol komut 17 ile tekrarlanır. Kritik nokta: program her döngüde komut göndermez, sadece durum değiştiğinde gönderir. Kod bunu şöyle sağlıyor:

main.c — relay_set() 
static void relay_set(int relay, int enabled)
{
    u8 command;

    if (relay < 0 || relay >= RELAY_COUNT) return;

    /* Durum zaten aynıysa hiçbir şey yapma.
       Bu olmasaydı saniyede yüzlerce USB paketi giderdi. */
    if (relay_state[relay] == (enabled ? 1 : 0)) return;

    relay_state[relay] = enabled ? 1 : 0;
    command = enabled ? relay_on_command[relay] : relay_off_command[relay];

    relay_send_command(command);
    show_relay_event(relay, enabled, command);
}

Ayrıca kol çıkarılırsa veya bağlantı bozulursa relays_all_off() çağrılır. Bu bir güvenlik davranışı: kol koptuğunda röle çekili kalmamalı.

4. USB'den veri göndermek — en basit hali

Projenin geri kalanını (menüler, şifre, hafıza kartı) çıkarırsan, PS2'den bir USB HID cihaza veri göndermek aslında üç adımdır.

Adım 1 — Cihazı tanı (probe)

usbd.irx her yeni USB cihazda senin sürücünün probe fonksiyonunu çağırır ve "bu cihaz seni ilgilendiriyor mu?" diye sorar. 1 dönersen cihaz senindir.

iop/seda_relay_irx.c — sadeleştirilmiş 
static int seda_probe(int dev_id)
{
    UsbDeviceDescriptor *dev;

    /* Cihazın kimlik kartını oku */
    dev = sceUsbdScanStaticDescriptor(dev_id, NULL, USB_DT_DEVICE);
    if (!dev) return 0;

    /* Benim aradığım cihaz mı? */
    if (dev->idVendor != target_vid || dev->idProduct != target_pid)
        return 0;

    return 1;   /* evet, bu benim */
}

Adım 2 — Bağlan ve bir "boru" (pipe) aç

USB'de veri, endpoint denen kanallardan akar. Bir endpoint'e yazmak için önce sceUsbdOpenPipe ile bir tutamak (handle) alman gerekir.

iop/seda_relay_irx.c — sadeleştirilmiş 
static int seda_connect(int dev_id)
{
    UsbConfigDescriptor    *conf;
    UsbInterfaceDescriptor *intf;
    UsbEndpointDescriptor  *out_ep;

    conf = sceUsbdScanStaticDescriptor(dev_id, dev, USB_DT_CONFIG);
    intf = find_hid_interface(dev_id, conf);        /* HID arayüzünü bul */

    /* Kontrol borusu: her USB cihazda vardır, endpoint 0.
       İkinci parametre NULL ise "endpoint 0" demektir. */
    relay_dev.control_ep = sceUsbdOpenPipe(dev_id, NULL);

    /* Interrupt OUT borusu: varsa asıl bunu kullanacağız */
    out_ep = find_interrupt_out_endpoint(intf, conf);
    if (out_ep)
        relay_dev.interrupt_out_ep = sceUsbdOpenPipe(dev_id, out_ep);

    /* Cihazı yapılandır (SET_CONFIGURATION) */
    sceUsbdSetConfiguration(relay_dev.control_ep,
                            conf->bConfigurationValue,
                            config_done, &relay_dev);
    return 0;
}

Adım 3 — Paketi gönder

İşte tüm işin özü. 8 bayt hazırla, boruya yaz, sonucu bekle:

iop/seda_relay_irx.c — özü 
/* 1) Paketi hazırla */
memset(relay_dev.report, 0, sizeof(relay_dev.report));
relay_dev.report[0] = 0x01;          /* sabit başlık */
relay_dev.report[3] = (u8)command;   /* 1..4 = ON, 17..20 = OFF */

/* 2) Gönder — bu çağrı ANINDA döner, iş bitmiş değildir */
start_result = sceUsbdInterruptTransfer(
    relay_dev.interrupt_out_ep,   /* hangi boru      */
    relay_dev.report,             /* veri            */
    8,                            /* kaç bayt        */
    transfer_done,                /* bitince çağrılacak fonksiyon */
    &relay_dev);                  /* callback'e geçilecek veri    */

/* 3) Bitmesini bekle */
result = wait_transfer_result(start_result);

En önemli kavram: USB transferleri asenkrondur. sceUsbdInterruptTransfer "gönder" demez, "gönderme işini kuyruğa al" der ve hemen geri döner. Veri gerçekten gittiğinde usbd.irx senin verdiğin callback fonksiyonunu çağırır. Bu yüzden kodda bir semafor (done_sema) var:

iop/seda_relay_irx.c — bekleme mekanizması 
/* usbd.irx transfer bitince BUNU çağırır */
static void transfer_done(int result, int bytes, void *arg)
{
    relay_dev.transfer_result = result;
    relay_dev.transfer_bytes  = bytes;
    SignalSema(done_sema);        /* "bitti" bayrağını kaldır */
}

/* Biz de bayrağı bekleriz — en fazla 3 saniye */
static int wait_transfer_result(int start_result)
{
    int i;
    if (start_result != USB_RC_OK) return start_result;

    for (i = 0; i < 300; i++) {
        if (PollSema(done_sema) == 0)      /* bayrak kalktı mı? */
            return relay_dev.transfer_result;
        DelayThread(10000);                /* 10 ms uyu, tekrar bak */
    }

    relay_dev.transfer_result = -1000;     /* timeout */
    return relay_dev.transfer_result;
}

5. EE ile IOP nasıl konuşuyor (SIF RPC)

İki işlemci arasında SIF adında bir donanım köprüsü var. Üzerinden uzaktan fonksiyon çağırma (RPC) yapılır: EE bir yapı doldurup gönderir, IOP işler, aynı yapıyı geri yollar. Tıpkı bir ağ isteği gibi ama iki çip arası.

İki tarafın da bilmesi gereken ortak tanımlar tek başlıkta toplanmış:

seda_relay_rpc.h — iki taraf da bunu include eder 
#define SEDA_RELAY_RPC_ID 0x5344524c   /* "SDRL" — servisin adresi */

#define SEDA_RELAY_RPC_SEND_COMMAND 1
#define SEDA_RELAY_RPC_GET_STATUS   2

typedef struct {
    int result;            /* IOP doldurur: işlem sonucu   */
    int command;           /* EE doldurur:  1..20          */
    int mode;              /* EE doldurur:  gönderim modu  */
    int status;            /* IOP doldurur: bağlı mı?      */
    int control_result;    /* teşhis için                  */
    int interrupt_result;  /* teşhis için                  */
} SedaRelayRpcPacket;

IOP tarafı servisi kaydeder ve sonsuz bir döngüde istek bekler:

static void rpc_thread(void *arg)
{
    sceSifInitRpc(0);
    sceSifSetRpcQueue(&rpc_queue, GetThreadId());
    sceSifRegisterRpc(&rpc_server, SEDA_RELAY_RPC_ID,
                      rpc_handler, &rpc_buffer, NULL, NULL, &rpc_queue);
    sceSifRpcLoop(&rpc_queue);      /* buradan asla çıkmaz */
}

EE tarafı önce servisi bulur (bind), sonra çağırır:

/* Bir kereye mahsus: servisi bul */
SifBindRpc(&relay_rpc, SEDA_RELAY_RPC_ID, 0);

/* Her komutta: çağır */
relay_rpc_packet.command = command;
relay_rpc_packet.mode    = usb_send_mode;

SifCallRpc(&relay_rpc,
           SEDA_RELAY_RPC_SEND_COMMAND,
           0,                                  /* 0 = bitene kadar bekle */
           &relay_rpc_packet, sizeof(...),     /* gönderilen  */
           &relay_rpc_packet, sizeof(...),     /* geri gelen  */
           NULL, NULL);

Neden __attribute__((aligned(64))) var? SIF köprüsü DMA ile çalışır ve DMA, verinin bellekte belirli bir sınıra hizalı olmasını ister. Hizalamayı unutursan veri bozulur veya hiç gitmez — üstelik hata mesajı da almazsın. Bu yüzden RPC ile taşınan her tampon hizalı tanımlanmış. Aynı sebeple pad_buf da 64'e hizalı.

Bind işleminin bir inceliği daha var: IRX yüklendikten hemen sonra RPC servisi henüz hazır olmayabilir. Kod bu yüzden bind_relay_rpc() içinde 120 kez deneyip aralarda nopdelay() ile bekliyor.

6. Röle kartının protokolü ve 12 mod meselesi

Kartın üreticisi protokolü yayınlamamış. Elde tek referans, Windows'ta çalışan C# programı vardı — windows-test/SedaRelayHid.cs: 

byte[] outputBuffer = new byte[9];
outputBuffer[0] = 0;          /* report ID */
outputBuffer[1] = 1;
outputBuffer[4] = command;
writeRawReportToDevice(outputBuffer);

Buradaki problem şu: Windows'un HID sürücüsü, gönderilen tamponun ilk baytını report ID olarak yorumlar ve kabloya çıkarken bu baytı kendisi işler. Yani telde gerçekten ne gittiği, uygulamanın gördüğü diziden farklıdır. PS2'de ise paketi ham haliyle sen yazıyorsun. Bu belirsizlik yüzünden kodda iki farklı paket biçimi ve toplam 12 gönderim modu var: 

/* Biçim A — Windows tamponunun birebir kopyası */
static void fill_seda_report(int command, int command_index)
{
    memset(relay_dev.report, 0, sizeof(relay_dev.report));
    relay_dev.report[0] = 0x00;
    relay_dev.report[1] = 0x01;
    relay_dev.report[command_index] = (u8)command;   /* genelde index 4 */
}

/* Biçim B — report ID atılmış hali; ÇALIŞAN BU */
static void fill_seda_payload_report(int command)
{
    memset(relay_dev.report, 0, sizeof(relay_dev.report));
    relay_dev.report[0] = 0x01;
    relay_dev.report[3] = (u8)command;
}

Biçim B, Biçim A'nın bir bayt sola kaymış halidir — tam olarak Windows'un report ID'yi yutmasıyla açıklanan fark. Varsayılan mod bu yüzden SEDA_RELAY_MODE_INT_PAYLOAD8 (mod 9): 8 baytlık interrupt OUT, report ID yok.

Diğer 11 mod birer teşhis aracı. Ayarlar ekranından mod değiştirip hangisinin tuttuğunu deneyebiliyorsun. MODE_AUTO (mod 0) ise kaba kuvvet uygular: uzunluk × rapor tipi × alıcı kombinasyonlarını sırayla dener, ilk tutanı kullanır. Bu döngü seda_send_command fonksiyonunun sonundadır.

Bundan çıkarılacak genel ders: dokümante olmayan bir USB cihazla çalışırken, doğru paketi tek denemede bulamazsın. Kodun içine "parametreleri değiştirilebilir bir deneme mekanizması" koymak — üstelik bunu cihazın kendi ekranından ayarlanabilir yapmak — her seferinde yeniden derleyip diske yazmaktan çok daha hızlıdır. Bu projedeki mod sistemi ve VID/PID düzenleme ekranı tam olarak bu yüzden var.

7. Röle kartına bağlantı ve elektrik

Seda Elektronik kartta iki USB bağlantısı kullanılır: biri kartın 5 V güç beslemesi, diğeri HID veri bağlantısıdır. İkisi PS2 Slim'in iki USB portuna bağlıdır. Asıl motor gücü kartın röle kontakları tarafındadır; PS2 USB hattından gelmez.

PS2 USB portu 1 ---- 5 V güç USB'si ----+ PS2 USB portu 2 ---- HID veri USB'si ---+---- [ Seda 8'li röle kartı ] | 3S LiPo (+) ---- NO1..NO4 | ilk dört röle 3S LiPo (-) ---- NC1..NC4 | v [COM1, COM2] ---- paralel iki sol RS-540 motorun iki ucu [COM3, COM4] ---- paralel iki sağ RS-540 motorun iki ucu Bir grupta tek röle ON: motor döner İki röle OFF: iki uç (-), motor durur İki röle ON: iki uç (+), motor durur

Rölenin üç ucu vardır ve mantığı şudur:

UçAnlamıRöle boştaykenRöle çekiliyken
COMOrtak uçHer zaman devrede
NONormalde açıkKopukCOM'a bağlı
NCNormalde kapalıCOM'a bağlıKopuk

Bu aracın çift yön bağlantısında bütün NC uçları LiPo (−), bütün NO uçları LiPo (+) hattındadır. COM1-COM2 sol motor grubunun, COM3-COM4 sağ motor grubunun uçlarına gider. Bu nedenle aynı grubun iki rölesinin birlikte ON olması besleme kısa devresi değildir; motorun iki ucunu da (+) yaparak motoru durdurur.

Akım uyarısı — atlanırsa donanım yakar.

  • Mevcut Seda kartın ayrı 5 V güç USB'si PS2'nin bir USB portuna bağlıdır; HID veri kablosu ikinci USB portundadır. Kartın üretici akım gereksinimini ve PS2 portundaki 5 V gerilimi yük altında ölç.
  • Bobin ile mikrodenetleyici arasında mutlaka sürücü olmalı: ULN2003/ULN2803 veya transistör. Tercihen optokuplör ile galvanik izolasyon.
  • Her bobinin uçlarına freewheel (snubber) diyot — bobin bırakırken oluşan ters gerilim spike'ı sürücü transistörünü öldürür. Hazır kartlarda genelde takılıdır ama kendi kartını yaparsan unutma.
  • Bobin diyodu ile motor bastırmasını karıştırma. Motor polaritesi ters çevrildiği için motor uçlarına tek yönlü 1N5408 bağlanmaz; çift yönlü TVS veya uygun RC snubber gerekir.
  • Şebeke gerilimi (220V) anahtarlıyorsan kart üzerinde düşük gerilim ve yüksek gerilim bölgeleri arasındaki mesafeye dikkat.

main.c içinde ilgi çekici birkaç yer

  • Ekrana yazma: log_printf() aynı metni hem printf (emülatör/ps2client konsoluna) hem scr_vprintf (TV ekranına) basar. Teşhis için çok pratik.
  • Ayar dosyası: mc0:SYS-CONF/ROLECFG.TXT — düz metin, mode=9 / vid=178E gibi satırlar. Binary format yerine metin seçilmiş, elle düzenlenebilir olması için.
  • Şifre ekranı: Ayarlara girmek için 12 tuşluk dizi (XXX □□□ △△△ ○○○). Amaç güvenlik değil, kullanıcının yanlışlıkla ayar bozmasını önlemek.
  • Tuş kenar tespiti: current_buttons = 0xffff ^ buttons.btns; — PS2'de kol tuşları ters mantıkla gelir (basılı = 0). XOR ile düzeltilir. Sonra pressed = current & ~previous ile "yeni basıldı", released = previous & ~current ile "yeni bırakıldı" bulunur.

9. Derleme ve çalıştırma

Derleme sırası önemlidir, çünkü EE tarafı IOP tarafının çıktısını içine gömer:

iop/seda_relay_irx.c --derle--> iop/seda_relay.irx | bin2c ile C dizisine çevir v seda_relay_irx.c | $(PS2SDK)/iop/irx/usbd.irx --bin2c--> usbd_irx.c | main.c + usbd_irx.c + seda_relay_irx.c ---+--> relay.elf | role.elf (kopya) | disc/ROLE.ELF + SYSTEM.CNF | role-disc.iso

Pratikte tek komut:

powershell -ExecutionPolicy Bypass -File build-disc.ps1

Bu betik önce build.ps1'i çağırır (PS2SDK yollarını ayarlar, make clean + make yapar), sonra MSYS2'nin xorriso'su ile ISO'yu üretir. Sadece ELF yeterliyse build.ps1'i tek başına çalıştırmak yeterli.

relay.elf geliştirici hata ayıklama bilgilerini korur. Hafıza kartına kopyalanacak role.elf ise aynı giriş adresi ve aynı çalışan LOAD segmenti korunarak otomatik olarak --strip-debug işleminden geçirilir. Bu nedenle dağıtım dosyası çok daha küçüktür; PS2'ye aktarırken daima role.elf kullan.

Emülatör sınırı: PCSX2 ile programın kol, ekran, menü ve hafıza kartı kısımlarını test edebilirsin — loglarda bunların yüklendiği görülüyor. Ama gerçek USB cihaz geçişi emülatörde güvenilir değildir. Röle protokolünü ancak gerçek konsolda doğrulayabilirsin. Bu yüzden ekrandaki result / status / ctrl / int sayıları önemli: konsolda TV'ye bakarak hata ayıklamanın tek yolu onlar.

10. Hareket programlama modu

Normal sürüşte START tuşu kayıt modunu açar ve güvenlik için bütün röleleri hemen kapatır. Bu modda hareket tuşları motorları anlık çalıştırmaz; en fazla 128 adımlık RAM dizisine kaydedilir. X, Yuvarlak, Üçgen ve Kare sürüş hareketidir; R1 bütün röleler kapalıyken bir saniye bekleme adımı ekler.

İkinci START kaydı yürütür. Her kayıt bir saniyedir. Art arda aynı hareket varsa röle arada bırakılmaz; örneğin X, X iki saniye kesintisiz ileri gider. Her farklı hareketin sonunda bütün röleler kapatılır ve sıradaki hareket uygulanır. Program tamamlanınca kayıt temizlenir ve röleler kapalı kalır.

SELECT kayıt sırasında programı iptal eder; yürütme sırasında 10 ms aralıklarla okunarak acil durdurma görevi görür. Her iki durumda da tüm röleler kapatılır. Normal moddaki R1 ayar ekranı davranışı korunur. START+SELECT birleşimi PS2 ana menüsüne dönmeye devam eder.

Güvenli kapatma: Yazılım kartta doğrulanmamış toplu 0xFC komutunu kullanmaz. Her tam kapatmada kartta doğrulanmış ayrı 17, 18, 19, 20 OFF komutlarını gönderir. Bir OFF komutu doğrulanamazsa program sonraki yönü enerjilendirmez. Böylece program geçişi, SELECT acil durdurması ve kontrolcü bağlantısının kopması aynı güvenli kapatma yolunu kullanır.

10.1 Röle ölü zamanı (dead time)

Bir yönden ters yöne geçerken röle kontakları aynı anda kapalı kalmamalı. Bu yüzden yazılım, canlı sürüşte bir röle kapatıldığı anda bütün kapatma işlemlerini tamamlayıp ayarlanabilir beklemeyi uygular; bundan sonra ters röle açılabilir. Program yürütmede bekleme, bir sonraki röleyi enerjilendirmeden hemen önce uygulanır. Varsayılan 100 ms; ayar ekranındaki Dead time satırından SOL/SAĞ ile 10 ms adımlarla 0-1000 ms arasında değiştirilir ve hafıza kartına deadms= anahtarıyla kaydedilir.

Bekleme yalnızca gerçekten borçluyken uygulanır:

  • Canlı sürüşte enerjili bir röle bırakılırsa; buna X ile Üçgen kısa süre üst üste tutulduktan sonra birinin bırakılması da dahildir.
  • relays_all_off() çalıştıktan sonraki ilk enerjilendirmede — program yürütmede her adım arası bu yola girer.

Canlı sürüşte bekleme röle kapanırken tamamlandığı için daha sonra yapılan bağımsız bir basışa ek gecikme eklenmez. Program yürütmede her farklı hareket adımı 1 sn açık + 100 ms ölü zaman olur; altı adımlık bir program yaklaşık 6,5 sn sürer.

10.2 Programı hafıza kartına kaydetme ve tek tuşla çağırma

Kayıt (programlama) modunda:

  • L1 — o anki diziyi hafıza kartına yazar.
  • L2 — kayıtlı diziyi karttan RAM'e geri yükler (üzerine ekleyip tekrar kaydedebilirsin).

Normal sürüş ekranında L2 tek tuşla kayıtlı programı karttan okur ve hemen çalıştırır. Kart boşsa veya dosya bozuksa uyarı verir, hiçbir röleye dokunmaz.

Dosya mc0:SYS-CONF/ROLEPRG.TXT yolunda düz metindir:

ROLEPRG v1
steps=XXOTSW

Harfler: X = X, O = Yuvarlak, T = Üçgen, S = Kare, W = bekleme. Okuyucu küçük harfi, aradaki virgül ve boşlukları da kabul eder; tanımadığı bir harf görürse dosyayı reddeder ve mevcut diziye dokunmaz. En fazla 128 adım okunur.

Özet: aklında kalması gerekenler

  1. PS2'de USB'ye EE değil IOP erişir. Projenin ikiye bölünmüş olmasının tek sebebi budur.
  2. İki taraf SIF RPC ile konuşur; taşınan yapı seda_relay_rpc.h'de tanımlıdır ve DMA yüzünden hizalı olmak zorundadır.
  3. USB'den veri göndermek özünde üç adımdır: probe (bu cihaz benim mi) → openPipe (boru aç) → transfer (yaz ve callback'i bekle).
  4. USB transferleri asenkrondur; fonksiyon dönmesi işin bittiği anlamına gelmez.
  5. Kart 8 baytlık interrupt OUT paketi bekler: byte[0]=0x01, byte[3]=komut.
  6. Röle bobinleri USB'den beslenmez; ayrı besleme + sürücü + freewheel diyot şarttır.
  7. Yeni bir HID cihaz (örneğin PIC18F4550 veya PIC16F1455 ile yapacağın kart) aynı paket formatını uygularsa, PS2 tarafında tek satır kod değiştirmeden çalışır — VID/PID'yi ayarlar ekranından girmen yeterlidir.
