# 0.4.35 — physical USB enumeration diagnostics

The device list previously showed only successfully enumerated devices. A read-only USBD extension now snapshots root-port connection, enable, low-speed and overcurrent flags, current enumeration state and the last enumeration error. The integrated IOP driver carries this snapshot in existing RPC padding; /devices and ?ls=devices include usbRoot and resetBusy. No EE native-job memory access is used. Stage 2 is SET_ADDRESS; stage 3 is device descriptor; stage 4 configuration; stage 5 the new default-address probe. Errors are historical until the next error/reboot; they are not a measured relay-contact state. Refresh the device inventory to refresh the snapshot.

Low-speed enumeration now waits 101 ms after reset and reads the first eight device-descriptor bytes at address zero before setting the address. Full-speed enumeration is unchanged. Short/malformed responses restart enumeration; unplugged callbacks do not proceed. The global default-address reset token remains held during the probe.

Physical result on the owner's unloaded, two-relay board connected directly to the console: port 1 was connected, enabled and low-speed, with no reported overcurrent. 0.4.34 recorded SET_ADDRESS no-response (USB code 5). After the descriptor-first compatibility change, 0.4.35 recorded GET_DESCRIPTOR no-response at address zero (stage 5, code 5). The board still did not enumerate; its actual VID/PID could not be read and no relay pulse was performed. The expected 16C0:05DF / USBRelay2 identity comes from the referenced host protocol, not from this board. No claim of relay-driver support or hardware repair is made.

Tests passed: actual low-speed helper with mocked transfers (valid, short, malformed, error and unplug), USB inventory/DMA ownership, bounded JSON/root flag decoding and native EE/IOP startup/gamepad regression. Both remote console restarts returned to Wi-Fi; 0.4.35 was observed running with gamepad ready and max observed pad gap 11 ms. The final 812,232-byte mc0:/Wifi/WIFI.ELF was installed and checked by HEAD size only, without downloading it or retaining a card backup.
