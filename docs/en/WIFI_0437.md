# 0.4.37 — targeted relay recovery and startup signal

This release includes the unpublished 0.4.36 root-port recovery fix. A connected
root USB port that lost ENABLE could remain stuck in the software READY state,
leaving relay commands unanswered until unplug/replug. It now retires the stale
device and schedules normal enumeration, without resetting the healthy peer.

The relay driver also attempts recovery after roughly five seconds of failed
status polling. A new USBD extension checks the relay VID/PID and resets only
that leaf device's port. Hubs, mismatched devices and root overcurrent states
are rejected. Without a usable device identity, recovery falls back to rebinding
only the relay driver. This is port reset/re-enumeration, **not physical VBUS
power cycling**. DMA buffers remain protected until endpoint retirement.

After rediscovery, all eight OFF commands must be acknowledged before driving
can resume. Failed OFF commands retain an uncertain output state. Previous
movement is cleared and controls must be released before driving again.

## Wiring-specific startup behavior

After initial all-OFF synchronization, **R1 is turned ON once for at least
100 ms and then OFF**. This pulse does not repeat on USB reconnection. The
owner confirmed R1 is physically unused, even though the saved software group
may include R1. **Do not use this build unchanged if R1 controls a motor or
another load that must not start automatically.** USB failure during the pulse
can delay OFF; this software is not an independent emergency power cutoff.

## Logging and verification

The log records boot, device-ready/lost transitions, USB command/mode/result
codes, recovery results, all-OFF synchronization and startup pulse phases.
A 16-event mailbox replaces the single-message mailbox; overflow is reported.
Lifecycle notices use the existing error sink, so they also carry its ERROR
label. If the clock is unavailable, timestamps fall back to uptime. Full or
unwritable storage and power loss can prevent persistence.

Local validation passed: 1,934 production EE scheduler checks including a
single startup pulse and 60-second gamepad/web holds, 19 production IOP lifecycle
cases, target-reset identity/root/hub guards, root-reset timer regressions,
browser control tests and native MIPS headless/gamepad regressions.

On the physical PS2, the 815,024-byte ELF was installed, checked by HEAD size
only, and observed running as 0.4.37 after one remote restart. Wi-Fi, gamepad
and relay were ready; all-OFF and one R1 ON/OFF sequence were acknowledged in
the console log. No motor-motion test or deliberate physical USB fault was
performed. The initiating cause of the previous USB outages remains unproven;
recovery changes do not establish that electrical faults are repaired.
